# Vault — веб-версия кейс-механики (демо, деплой через сайт Vercel)

> Эта папка — самодостаточный проект: всё содержимое рассчитано на то, чтобы
> лежать прямо в корне git-репозитория. Чтобы заменить старую версию новой:
> удалите из репозитория всё, кроме `.git/`, скопируйте сюда содержимое этой
> папки целиком (включая скрытые файлы `.gitignore`, `.env.example`), закоммитьте
> и запушьте — Vercel пересоберёт проект автоматически по пушу в `main`.

Тот же движок кейсов, что и раньше, но:
- без Telegram — пользователь идентифицируется анонимной cookie-сессией
  (`lib/session.ts`), это легко заменить на `telegram_id`, когда дойдёте до бота;
- вся логика начисления/списания/кулдауна/розыгрыша вынесена в `lib/`, так что
  при переносе на Telegram-бота эти файлы можно переиспользовать почти
  без изменений — поменяется только "кто такой userId" и слой доставки
  сообщений (веб UI → Telegram API).

**Напоминание из прошлых ответов остаётся в силе**: VPN-ссылки и AI-доступ
здесь — заглушки (`lib/mockSatellites.ts`), реального реселлинга LLM API и
реальной выдачи VPN нет — большинство провайдеров это запрещает в ToS, а
для кейсов за реальные деньги стоит отдельно свериться с местным
законодательством об азартных играх.

## Стек

Next.js 14 (App Router) + Tailwind + Upstash Redis (хранилище баланса,
терминов, кулдауна бесплатного кейса — обычный SQLite тут не подходит,
т.к. Vercel serverless не хранит файлы между запросами).

## Деплой через сайт vercel.com (без CLI)

### 1. Залейте проект в GitHub

Vercel деплоит из git-репозитория. Создайте новый репозиторий на GitHub и
запушьте туда содержимое этой папки (`case_bot_web/` → в корень репозитория).
Если раньше не работали с git:

```bash
cd case_bot_web
git init
git add .
git commit -m "vault: initial prototype"
git branch -M main
git remote add origin https://github.com/<ваш_аккаунт>/<репозиторий>.git
git push -u origin main
```

### 2. Импортируйте проект на vercel.com

1. Зайдите на https://vercel.com → **Add New → Project**.
2. Выберите только что созданный репозиторий → **Import**.
3. Vercel сам определит, что это Next.js — framework preset и команды
   сборки (`next build`) подставятся автоматически, ничего менять не нужно.
4. Пока не нажимайте Deploy — сначала подключите Redis (следующий шаг),
   иначе первый билд задеплоится без переменных окружения.

### 3. Подключите Upstash Redis прямо из дашборда Vercel

1. В настройках проекта (или на экране импорта) откройте вкладку
   **Storage → Create Database → Upstash → Redis**.
2. Выберите бесплатный тариф, регион — ближайший к вам.
3. Нажмите **Connect** к вашему проекту — Vercel сам добавит переменные
   окружения `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` во все
   окружения (Production/Preview/Development). Вручную ничего вписывать
   не нужно — `lib/redis.ts` использует `Redis.fromEnv()` и подхватит их
   автоматически.

Если предпочитаете завести Redis отдельно на upstash.com — тоже ок, тогда
просто вручную добавьте эти две переменные в **Settings → Environment
Variables** проекта на Vercel.

### 4. Deploy

Нажмите **Deploy**. Через 1–2 минуты получите адрес вида
`https://vault-xxxxx.vercel.app` — сайт уже полностью рабочий.

Дальше при каждом `git push` в `main` Vercel будет пересобирать и
выкатывать новую версию автоматически.

## Локальный запуск (проверить перед деплоем)

```bash
cd case_bot_web
npm install
cp .env.example .env.local   # впишите туда UPSTASH_REDIS_REST_URL/TOKEN
npm run dev
```
Откройте http://localhost:3000.

## Что уже работает

- принятие пользовательского соглашения (гейт при первом визите);
- баланс поинтов (Redis, привязан к анонимной сессии);
- временная демо-кнопка "+500 (демо)" вместо платёжного шлюза;
- 4 кейса из ТЗ с точными вероятностями, честный ролл через `crypto.randomInt`
  (CSPRNG) на сервере — фронтенд получает уже готовый результат, подделать
  через devtools нельзя;
- анимация открытия кейса (прокрутка ленты с остановкой на призе);
- кулдаун 7 дней на бесплатный кейс (антифрод, как в исходном ТЗ);
- мок-выдача VPN-ссылки / AI-гранта.

## Что нужно доделать перед реальным (не демо) запуском

1. **Уберите `/api/debug-add-points`** — сейчас это открытый эндпоинт, любой
   посетитель сайта может начислить себе поинты бесплатно. Замените на
   настоящий платёжный шлюз (Stars/фиат-эквайринг) с проверкой платежа на
   сервере перед начислением.
2. **`spendPoints()` в `lib/storage.ts` не атомарен** (GET, потом HINCRBY
   отдельными запросами) — при параллельных запросах баланс теоретически
   можно потратить дважды. Для продакшна замените на Redis Lua-скрипт
   (`EVAL`) с проверкой-и-списанием одной атомарной командой.
3. **Реальная VPN/AI-выдача** намеренно оставлена моками — см.
   `lib/mockSatellites.ts` и объяснение в предыдущих ответах про ToS
   провайдеров.
4. Anti-bot проверки (капча, ограничение по IP/устройству) не реализованы —
   cookie-сессию легко сбросить, открыв сайт в приватном окне.
5. Когда будете переносить на Telegram: замените `lib/session.ts`
   (cookie-сессия) на `telegram_id` из апдейта бота — `lib/storage.ts` и
   `lib/cases.ts` менять не придётся, они уже написаны через абстрактный
   `userId`.

## Структура

```
case_bot_web/
├── app/
│   ├── layout.tsx, page.tsx, globals.css
│   └── api/
│       ├── session/route.ts          GET  — сессия + баланс
│       ├── accept-terms/route.ts     POST — принять соглашение
│       ├── cases/route.ts            GET  — каталог кейсов + шансы
│       ├── open-case/route.ts        POST — открыть кейс
│       └── debug-add-points/route.ts POST — [DEMO ONLY] пополнение
├── components/
│   ├── VaultApp.tsx      главный клиентский компонент
│   ├── CaseCard.tsx, CaseOpener.tsx, BalanceBadge.tsx, TermsGate.tsx
├── lib/
│   ├── cases.ts           механика и веса кейсов (CSPRNG)
│   ├── storage.ts         Redis-хранилище
│   ├── session.ts         анонимная cookie-сессия
│   ├── redis.ts, types.ts, mockSatellites.ts
```
