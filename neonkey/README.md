# NeonKey — сервис цифровых товаров (v2.1)

Обычный сайт + Telegram Mini App для продажи цифровых товаров (Steam,
Telegram Stars и т.д.) — теперь это два разных экрана одного продукта:

- **`webapp/`** (корень) — публичный сайт-визитка: лендинг с рассказом
  о сервисе, входом через Telegram и переходом в личный кабинет.
  Открывается в обычном браузере, в Telegram не встраивается.
- **`webapp/app/`** — сам сервис (профиль, каталог, оплата). Это и есть
  то, что открывается кнопкой бота как Telegram Mini App, и то, во что
  ведёт кнопка "Открыть каталог" с лендинга — при заходе с обычного
  браузера работает как полноценный личный кабинет на сайте.

Аккаунт один и тот же везде: вход по email или через Telegram, сессия
общая для лендинга и `/app/` (в рамках одного домена).

## Что нужно донастроить перед запуском

### 1. Supabase — регистрация без подтверждения почты
Регистрация по email настроена на самый простой вариант: email + пароль,
пользователь сразу внутри приложения, без писем и кодов. Для этого
нужно (один раз, руками, в панели Supabase):

1. Зайди в свой проект Supabase → **Authentication → Sign In / Providers → Email**.
2. Убедись, что тумблер **«Confirm email» выключен**.
3. Сохрани.

**Компромисс явно:** без подтверждения почты кто угодно может
зарегистрироваться на чужой/фейковый email — это осознанный выбор в
пользу простоты.

### 2. Ссылки на оплату товаров
1. Заведи товары в своей платёжной системе с ценой, уже включающей
   твою наценку, и получи ссылку на страницу оплаты каждого товара.
2. Вставь эти ссылки в `webapp/app/js/data/catalog.js`, поле
   `checkoutUrl`, для каждого товара.
3. Промокоды/скидки настраиваются на стороне платёжной системы и
   вводятся покупателем прямо на странице оплаты.

**Важно:** некоторые платёжные страницы запрещают показ себя во фрейме
(X-Frame-Options/CSP) — тогда покупатель нажмёт «Открыть в новой
вкладке» в окне оплаты. Это нормально, проверяется на реальных товарах.

### 3. Telegram-вход (Login Widget) — требует одноразовой настройки
Вход через Telegram проверяется не в браузере (токен бота нельзя
доверять клиентскому коду), а в Supabase Edge Function. Шаги:

1. **Домен бота.** У @BotFather → выбери бота → `/setdomain` → укажи
   домен, на котором будет висеть `webapp/` (например,
   `neonkey.vercel.app`). Без этого виджет Telegram Login не заработает.
2. **Деплой Edge Functions.** В папке `supabase/functions/` лежат две
   функции: `telegram-auth` (вход/регистрация через Telegram) и
   `telegram-link` (привязка Telegram к уже существующему аккаунту).
   Задеплой их через Supabase CLI:
   ```bash
   supabase functions deploy telegram-auth
   supabase functions deploy telegram-link
   ```
3. **Секреты функций.** В Supabase Dashboard → Edge Functions → Secrets
   пропиши:
   - `BOT_TOKEN` — тот же токен, что в `bot/config.py`/`.env`.
   - `SUPABASE_SERVICE_ROLE_KEY` — Settings → API → service_role key
     (⚠️ секретный ключ, никогда не должен попасть в webapp/).
   (`SUPABASE_URL` и `SUPABASE_ANON_KEY` Supabase обычно подставляет
   автоматически для Edge Functions в своём проекте.)
4. **Конфиг фронтенда.** В `webapp/app/js/config.js` укажи:
   - `BOT_USERNAME` — юзернейм бота без `@`.
   - `TELEGRAM_AUTH_FUNCTION_URL` — URL твоей функции `telegram-auth`
     (обычно `https://<project-ref>.functions.supabase.co/telegram-auth`).

Если пропустить эти шаги — вход по email продолжит работать как
раньше, просто кнопка "Войти через Telegram" будет выдавать ошибку.

### 4. Bot
Токен бота в `bot/config.py` — тестовый и уже "засвечен" в переписке,
перед публичным запуском обязательно отзови его через @BotFather →
`/revoke` и впиши новый в `.env` (см. `bot/.env.example`). Проверь, что
`SHOP_URL` указывает на `.../app/` (мини-апп), а не на корень сайта
(там теперь лендинг, который в Telegram открывать не нужно).

## Честная оговорка про историю заказов

На сайте больше нет своей таблицы заказов и нет вебхука от платёжной
системы, поэтому "Последние заказы" в профиле — это лог момента, когда
пользователь нажал «Купить» и открылось окно оплаты, а не подтверждение
того, что оплата прошла успешно. Настоящий статус заказа видит только
платёжная система. Если понадобится показывать реальный статус оплаты —
это отдельная задача (нужен вебхук от провайдера и своя запись о заказе).

## Локальный запуск
`webapp/` — статические файлы, достаточно любого HTTP-сервера
(например, `npx serve webapp` или деплой на Vercel/Netlify). Важно
отдавать и `webapp/index.html`, и `webapp/app/index.html` — то есть
деплоить всю папку `webapp/` целиком, а не только `app/`.

`bot/` — Python 3.11+, `pip install -r requirements.txt`, затем
`python main.py`.
