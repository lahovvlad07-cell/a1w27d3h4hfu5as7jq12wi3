# NeonKey — сайт цифровых товаров (v3.2)

Двухстраничный сайт: публичный лендинг **и отдельный личный кабинет**
за входом (каталог, профиль с аватаром, история заказов, информация о
проекте) — как это и должно быть, каталог не живёт на главной.

## Что изменилось в 3.2 (по итогам ревью)

- ✅ **Каталог убран с главной страницы полностью.** `index.html` — это
  теперь чистый лендинг: hero, «как это работает», футер. Ни одной
  кнопки «Купить» на главной больше нет.
- ✅ **Появилась вторая страница — `account.html`, личный кабинет.**
  Доступна только после входа (без сессии показывается экран
  «Войдите, чтобы продолжить»). Внутри — три вкладки:
  - **Каталог** — то, что раньше было на главной.
  - **Профиль** — аватар (клик по кружку открывает выбор из 16 эмодзи),
    имя/почта, статус способов входа (Email/Telegram), последние 5
    заказов, кнопка «Выйти».
  - **Информация** — «О проекте», FAQ, Политика конфиденциальности,
    Публичная оферта — тот же контент, что раньше был в Mini App.
- ✅ Кнопки «Открыть личный кабинет» на лендинге либо сразу ведут в
  `account.html` (если уже вошли), либо сначала открывают модалку
  входа и уже потом ведут в кабинет.

## Синхронизация с будущим Mini App

Когда будешь собирать Mini App отдельным проектом, чтобы данные не
разъехались:

1. **Один и тот же Supabase-проект.** Возьми `SUPABASE_URL` и
   `SUPABASE_ANON_KEY` из `webapp/js/config.js` — тогда вход (Telegram
   или email) и сайт создают/находят один и тот же аккаунт.
2. **Один и тот же каталог.** Держи `webapp/js/data/catalog.js`
   синхронным с каталогом в Mini App (те же `id`, `checkoutUrl`, цены).
3. **Формат истории заказов.** Сайт пишет последние 5 заказов в
   `user_metadata.orders` аккаунта (см. `js/lib/orders.js`) в простом
   формате `{ id, name, icon, price, date }`. Mini App может читать это
   же поле — не нужна отдельная таблица.
4. **Палитра.** Токены в `webapp/css/tokens.css` (голубой/сиреневый/
   розовый на почти чёрном, снято с `assets/logo.png`) — используй те же
   переменные и в Mini App, чтобы не было ощущения двух разных продуктов.
5. **Структура.** Mini App по смыслу ближе к `account.html` (кабинет),
   чем к `index.html` (лендинг) — в Telegram люди сразу открывают
   каталог/профиль, вступительный экран там не нужен.

## Что нужно донастроить перед запуском

### 1. Ссылки на оплату товаров
1. Заведи товары в своей платёжной системе с ценой, уже включающей
   твою наценку, и получи ссылку на страницу оплаты каждого товара.
2. Вставь эти ссылки в `webapp/js/data/catalog.js`, поле `checkoutUrl`,
   для каждого товара — пока там `null`, кнопка показывает бейдж «скоро».

**Важно:** некоторые платёжные страницы запрещают показ себя во фрейме
(X-Frame-Options/CSP) — тогда покупатель нажмёт «Открыть в новой
вкладке» в окне оплаты. Это нормально, проверяется на реальных товарах.

### 2. Вход через Telegram — требует одноразовой настройки на сервере
Email/пароль работает «из коробки» (это штатная функция Supabase Auth).
А вот вход через Telegram проверяется не в браузере (токен бота нельзя
доверять клиентскому коду), а в Supabase Edge Function — **пока она не
задеплоена, кнопка Telegram в модалке входа будет закономерно выдавать
ошибку «Не удалось связаться с сервером входа через Telegram»**. Это
не баг фронтенда, а недостающий шаг инфраструктуры:

1. **Домен сайта.** У @BotFather → выбери бота → `/setdomain` → укажи
   домен, на котором будет висеть `webapp/`. Без этого виджет Telegram
   Login не заработает.
2. **Деплой Edge Function.**
   ```bash
   supabase functions deploy telegram-auth
   ```
3. **Секреты функции.** В Supabase Dashboard → Edge Functions → Secrets
   пропиши:
   - `BOT_TOKEN` — тот же токен, что в `bot/config.py`/`.env`.
   - `SUPABASE_SERVICE_ROLE_KEY` — Settings → API → service_role key
     (⚠️ секретный ключ, никогда не должен попасть в `webapp/`).
4. **Конфиг фронтенда.** В `webapp/js/config.js` проверь `BOT_USERNAME` —
   юзернейм бота без `@`.

Пока не задеплоено — просто говори покупателям входить по email, это
не блокирует запуск сайта.

### 3. Bot
Токен бота в `bot/config.py` — тестовый, перед публичным запуском
обязательно отзови его через @BotFather → `/revoke` и впиши новый в
`.env` (см. `bot/.env.example`). `SHOP_URL` бота стоит направить на
будущий Mini App, когда он будет готов.

## Честная оговорка про историю заказов

У сайта нет своей таблицы заказов и нет вебхука от платёжной системы,
поэтому запись в `user_metadata.orders` — это лог момента, когда
пользователь нажал «Купить» и открылось окно оплаты, а не подтверждение
того, что оплата прошла успешно. Настоящий статус заказа видит только
платёжная система. Если понадобится показывать реальный статус оплаты —
нужен вебхук от провайдера и отдельная запись о заказе.

## Локальный запуск

`webapp/` — статические файлы, достаточно любого HTTP-сервера:
```bash
npx serve webapp
```
или деплой на Vercel/Netlify/Cloudflare Pages — просто указывай
`webapp/` как корень сайта.

`bot/` — Python 3.11+, `pip install -r requirements.txt`, затем
`python main.py`.
