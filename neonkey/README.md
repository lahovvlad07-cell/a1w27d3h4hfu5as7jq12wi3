# NeonKey — сайт цифровых товаров (v3.0)

Публичный сайт для продажи цифровых товаров (Steam, Telegram Stars и
т.д.): лендинг, каталог с оплатой прямо на странице и вход через
Telegram — всё в одном месте, без отдельного личного кабинета.

## Что изменилось в 3.0

Раньше в одном проекте были смешаны обычный сайт (`webapp/index.html`)
и Telegram Mini App (`webapp/app/`) — из-за этого каталог на главной
страницу технически зависел от модулей мини-аппа, а само оформление
сайта визуально не совпадало с версией для Telegram.

- ✅ **`webapp/app/` (Mini App) удалён из этого проекта.** Ты
  разрабатываешь его отдельно — см. раздел «Синхронизация с Mini App»
  ниже: что нужно оставить одинаковым, чтобы аккаунт и каталог не
  разъехались.
- ✅ **Сайт больше ни от чего не зависит** — все модули (каталог,
  оплата, вход, документы, тосты) теперь свои, лежат прямо в `webapp/js/`.
  Каталог на главной больше никуда не «улетает».
- ✅ **Полная пересборка дизайна**, под единую стилистику и с
  анимациями: hero с интерактивной «ключ-картой» (вход через Telegram
  встроен прямо в неё), секция «как это работает» с шагами, каталог в
  виде карточек-ключей с бейджами «доступно/скоро», скролл-анимации,
  единая система токенов дизайна (`webapp/css/tokens.css`).
- ✅ Личный кабинет с историей заказов на сайте больше не показывается
  (ему негде было жить без `/app/`) — но каждый клик «Купить» всё
  так же тихо пишется в `user_metadata` аккаунта, чтобы будущий Mini
  App мог прочитать эту историю без миграции данных.

    base.css                 сброс, фон, типографика, focus-стили

    sections.css               hero/ключ-карта, шаги, каталог, футер, адаптив

    lib/

    content/legalDocs.js         тексты Политики и Оферты (шаблон, показать юристу)
    main.js                       точка входа, склеивает всё вместе

supabase/
  functions/
    _shared/telegram.ts          проверка подписи Telegram Login Widget
    telegram-auth/                вход/регистрация через Telegram (использует сайт)
    telegram-link/                привязка Telegram к текущему аккаунту
                                   (пока не используется сайтом — пригодится,
                                   когда в Mini App появится экран профиля
                                   с привязкой email)

`supabase/` и `bot/` — это общий бэкенд для сайта и будущего Mini App,
поэтому они оставлены как есть и не относятся к «вырезанному» мини-аппу.

## Синхронизация с будущим Mini App

Когда будешь собирать Mini App отдельным проектом, чтобы данные не
разъехались:

1. **Один и тот же Supabase-проект.** Возьми `SUPABASE_URL` и
   `SUPABASE_ANON_KEY` из `webapp/js/config.js` — тогда Telegram-вход и
   сайт создают/находят один и тот же аккаунт.
2. **Один и тот же каталог.** Держи `webapp/js/data/catalog.js`
   синхронным с каталогом в Mini App (те же `id`, `checkoutUrl`, цены).
   Проще всего — вынести файл в общий пакет/репозиторий, когда дойдут руки.
3. **Формат истории заказов.** Сайт пишет последние 5 заказов в
   `user_metadata.orders` аккаунта (см. `js/lib/orders.js`) в простом
   формате `{ id, name, icon, price, date }`. Mini App может просто
   читать это же поле — не нужна отдельная таблица.
4. **Не обязательно копировать дизайн 1:1.** Токены в
   `webapp/css/tokens.css` (цвета, типографика, тайминги) — хорошая
   отправная точка для визуальной идентичности Mini App, но сама
   стилистика в Telegram может быть компактнее (мобильный шелл, а не
   полноценный лендинг).

## Что нужно донастроить перед запуском

### 1. Ссылки на оплату товаров
1. Заведи товары в своей платёжной системе с ценой, уже включающей
   твою наценку, и получи ссылку на страницу оплаты каждого товара.
2. Вставь эти ссылки в `webapp/js/data/catalog.js`, поле `checkoutUrl`,
   для каждого товара — пока там `null`, кнопка показывает бейдж «скоро».

**Важно:** некоторые платёжные страницы запрещают показ себя во фрейме
(X-Frame-Options/CSP) — тогда покупатель нажмёт «Открыть в новой
вкладке» в окне оплаты. Это нормально, проверяется на реальных товарах.

### 2. Telegram-вход (Login Widget) — требует одноразовой настройки
Вход через Telegram проверяется не в браузере (токен бота нельзя
доверять клиентскому коду), а в Supabase Edge Function. Шаги:

1. **Домен сайта.** У @BotFather → выбери бота → `/setdomain` → укажи
   домен, на котором будет висеть `webapp/`. Без этого виджет Telegram
   Login не заработает.
2. **Деплой Edge Function.**
   ```bash
   supabase functions deploy telegram-auth
   ```
3. **Секреты функции.** В Supabase Dashboard → Edge Functions → Secrets
   пропиши:
   - `BOT_TOKEN` — тот же токен, что в `bot/config.py`/`.env`.
   - `SUPABASE_SERVICE_ROLE_KEY` — Settings → API → service_role key
     (⚠️ секретный ключ, никогда не должен попасть в `webapp/`).
4. **Конфиг фронтенда.** В `webapp/js/config.js` укажи `BOT_USERNAME` —
   юзернейм бота без `@`.

Если пропустить эти шаги, каталог и оплата продолжат работать как
обычно — просто кнопка «Войти через Telegram» будет выдавать ошибку.

### 3. Bot
Токен бота в `bot/config.py` — тестовый, перед публичным запуском
обязательно отзови его через @BotFather → `/revoke` и впиши новый в
`.env` (см. `bot/.env.example`). `SHOP_URL` бота стоит направить на
будущий Mini App, когда он будет готов — сайт из этого репозитория в
Telegram открывать не нужно.

## Честная оговорка про историю заказов

У сайта нет своей таблицы заказов и нет вебхука от платёжной системы,
поэтому запись в `user_metadata.orders` — это лог момента, когда
пользователь нажал «Купить» и открылось окно оплаты, а не подтверждение
того, что оплата прошла успешно. Настоящий статус заказа видит только
платёжная система. Если понадобится показывать реальный статус оплаты —
нужен вебхук от провайдера и отдельная запись о заказе.

## Локальный запуск

`webapp/` — статические файлы, достаточно любого HTTP-сервера:
```bash
npx serve webapp
```
или деплой на Vercel/Netlify/Cloudflare Pages — просто указывай
`webapp/` как корень сайта.

`bot/` — Python 3.11+, `pip install -r requirements.txt`, затем
`python main.py`.
